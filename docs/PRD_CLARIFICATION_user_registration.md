## 按功能域展开

### 1. 注册表单

- 手机号输入框：仅支持 11 位中国大陆手机号（1 开头），输入时自动格式化为 `138-0000-0000`
- 短信验证码：6 位数字输入框，发送验证码按钮带 60 秒倒计时
- 密码输入框：两个（密码 + 确认密码），8-20 位，必须包含数字和字母，实时校验不一致提示
- 用户协议：勾选框 + "《用户协议》"可点击链接
- 注册按钮：所有字段合法 + 协议已勾选后方可点击

### 2. 验证码流程

- 发送前先校验手机号格式（11 位 / 1 开头）
- 发送前先校验手机号是否已注册 → 已注册则阻断，提示"该手机号已注册，请直接登录"并提供"去登录"链接
- 发送成功后按钮置灰 60 秒倒计时
- 验证码有效期 5 分钟，超时需重新获取
- 同一手机号可能有发送频率限制（由后端控制）

### 3. 密码校验

- 8-20 位
- 必须同时包含数字和字母（大写或小写均可）
- 实时校验：输入框失焦时提示，确认密码框实时比对
- 两个密码不一致时，确认密码框下方显示红色提示"两次输入的密码不一致"

### 4. 提交流程

- 成功：自动登录 → 跳转主页
- 失败（网络异常/服务端错误）：Toast "注册失败，请检查网络后重试"，留在当前页面，用户可修改后重新提交
- 页面状态：注册期间按钮显示 loading，禁止重复点击

### 5. 协议查看

- 勾选框旁显示"我已阅读并同意《用户协议》"
- "《用户协议》" 为可点击链接，点击后打开协议详情页（WebView 或内嵌页面）
- 未勾选时注册按钮不可点击

## 待确认项

以下为三轮澄清中未涵盖、PRD 生成前需确认的点：

1. 验证码发送方式：前端调短信服务商 API 还是后端统一发送？（推荐后端，安全可控）
2. 协议链接：WebView 加载远程 URL 还是本地静态文本？
3. "去登录"链接点击后：跳转登录页并自动填入手机号？
4. 注册页与登录页的导航关系：注册页是否有"已有账号？去登录"入口？
