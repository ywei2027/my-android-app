## 1. 功能概述

### 1.1 一句话描述
用户可以通过关键词搜索文章标题和内容，快速找到感兴趣的内容。

### 1.2 用户场景
| 场景 | 用户 | 操作 | 期望结果 |
|------|------|------|---------|
| S1-关键词搜索 | 普通用户 | 在搜索框输入关键词，点击搜索 | 返回匹配的文章列表，标题和正文摘要高亮关键词，默认按相关度排序（标题命中权重>正文命中） |
| S2-空关键词 | 普通用户 | 不输入内容直接搜索 | Toast提示"请输入搜索关键词"，焦点回到搜索框 |
| S3-无结果 | 普通用户 | 搜索一个不存在的关键词 | 显示空状态：插画 + "未找到相关结果" + "换个关键词试试" |
| S4-搜索历史 | 普通用户 | 点击搜索框（未输入） | 展示最近5条搜索历史，可点击复用、左滑删除单条、"清空全部"按钮（AlertDialog确认） |
| S5-网络错误 | 普通用户 | 搜索时网络断开 | Snackbar显示"网络连接失败，请检查网络后重试" + 重试按钮（Indefinite duration） |
| S6-加载更多 | 普通用户 | 搜索结果超过一页，滚动到底部 | 自动加载下一页，底部显示CircularProgressIndicator + "加载更多…" |
| S7-结果判断 | 普通用户 | 浏览搜索结果列表 | 摘要包含关键词上下文（非固定前N字截取），用户无需点击即可判断相关性 |
| S8-输入中状态 | 普通用户 | 在搜索框逐字输入 | 输入内容后出现一键清除按钮（×图标），输入时不做实时搜索（等待点击搜索/键盘确认） |
| S9-历史管理 | 普通用户 | 管理搜索历史 | 单条左滑显示红色删除按钮，底部"清空全部"点击后弹出AlertDialog确认 |

### 1.3 范围边界
- **包含**: 文章标题+正文全文搜索（默认相关度排序：标题命中权重 > 正文命中），搜索结果分页，搜索历史（本地存储5条，支持单条删除+全部清空），关键词高亮（AnnotatedString + primaryContainer背景色）
- **不包含**: 语音搜索，图片搜索，高级筛选（标签/时间/分类），搜索建议/自动补全（延后到v1.1），后端搜索引擎迁移
- **明确决策**: 搜索排序=相关度优先；搜索入口=首页SearchBar快捷入口 + 独立/search页

## 2. 页面与交互

### 2.1 页面清单
| 页面 | 路由 | 输入 | 输出 | 状态 |
|------|------|------|------|------|
| 搜索入口 | `/search` | 用户从首页点击搜索图标进入 | 搜索框 + 搜索历史列表 | 新建 |
| 搜索结果 | `/search?q={keyword}` | 关键词 | 文章列表（标题+摘要+高亮）+ 分页 | 新建 |
| 搜索结果-空 | `/search?q={keyword}` | 无匹配结果 | 空状态插画 + 提示文案 | 新建 |

### 2.2 关键交互流程
```
主路径：
  首页顶部SearchBar快捷入口 → 点击 → 独立搜索页 /search（展示历史记录）
  → 输入关键词 → 点击搜索/键盘确认
  → 搜索结果列表（标题+摘要高亮，关键词上下文摘要，相关度排序）
  → 点击结果项 → 文章详情页

分支路径：
  - 空输入搜索 → Toast"请输入搜索关键词"，焦点回到搜索框
  - 搜索无结果 → 空状态页（插画 + "未找到相关结果" + "换个关键词试试"）
  - 网络错误 → Snackbar（含"重试"按钮，Indefinite duration）
  - 清空搜索框 → 回到搜索历史页
  - 结果页修改关键词 → 顶部搜索框可编辑，原地修改再次搜索

搜索历史：
  - 每次成功搜索后 → DataStore 本地存储关键词（最近5条，去重）
  - 点击历史项 → 键盘收起 + 自动填入 + 触发搜索
  - 单条删除 → 左滑（SwipeToDismiss）+ 红色删除按钮
  - 全部清空 → 点击底部"清空全部" → AlertDialog确认 → 清除
```

### 2.3 键盘行为（分场景）
| 场景 | 键盘行为 |
|------|---------|
| 点击搜索按钮 | 键盘收起 + 发起搜索 |
| 点击历史记录 | 键盘收起 + 自动填入 + 触发搜索 |
| 点击搜索框外空白区域 | 键盘收起，不发起搜索 |
| 滚动搜索结果列表 | 键盘收起 |

### 2.4 状态文案规范
| 状态 | 主文案 | 副文案 | 操作 |
|------|--------|--------|------|
| 空关键词提交 | "请输入搜索关键词" | — | 焦点回搜索框 |
| 无搜索结果 | "未找到相关结果" | "换个关键词试试" | — |
| 搜索历史为空 | "暂无搜索历史" | — | — |
| 网络错误 | "网络连接失败" | "请检查网络后重试" | 重试按钮 |
| 加载中 | 骨架屏（3个placeholder item） | — | — |
| 分页加载失败 | "加载失败，请重试" | — | 重试按钮 |

### 2.5 动效规格
| 动效 | 实现方式 | 参数 |
|------|---------|------|
| 搜索框展开 | AnimatedVisibility + fadeIn + expandHorizontally | 300ms, FastOutSlowInEasing |
| 搜索结果条目入场 | slideInVertically + fadeIn | stagger 50ms per item |
| 搜索历史删除 | SwipeToDismiss + fadeOut | 红色垃圾桶图标 |
| 下拉刷新 | PullToRefresh | M3 默认样式 |

### 2.6 边界情况
| 情况 | 处理方式 |
|------|---------|
| 加载中 | 骨架屏（搜索框下方显示 3 个 placeholder item）|
| 空数据（无历史） | 显示"暂无搜索历史"提示文案 |
| 空数据（无结果） | 居中空状态插画（放大镜+文档）+ "未找到相关结果" + "换个关键词试试" |
| 网络错误 | Snackbar "网络连接失败，请检查网络后重试" + 重试按钮（Indefinite duration） |
| 权限不足 | 不涉及（搜索功能无需特殊权限）|
| 键盘处理 | 分3场景处理：点搜索→收起+搜索；点历史→收起+填入+搜索；点空白→仅收起 |
| 特殊字符输入 | 过滤 XSS 相关字符，限制输入长度 100 字符 |

## 3. 多视角评审记录

### 🎯 产品视角（Agent A）
> 评审人: Hermes-Product | 日期: 2026-05-31

| 维度 | 评价 | 建议 |
|------|------|------|
| 用户价值 | 痛点成立但不够尖锐——缺少量化目标来说明搜索功能的价值 | 补充量化目标：让用户从"翻分类→翻页→扫标题→点文章→发现不对→返回"5步操作降到"搜索→点开"2步 |
| 功能完整性 | 核心路径(S1-S6)覆盖完整，但有3个关键遗漏：排序逻辑悬置、搜索入口可见性未定义、搜索结果摘要规则缺失 | (1)默认排序为"相关度优先"(标题命中权重>正文命中)；(2)补充搜索入口设计——首页顶部搜索栏快捷入口；(3)摘要截取关键词上下文而非固定前N字 |
| 优先级合理性 | "不包含"排除了语音/图片搜索和高级筛选是正确的，但搜索建议/自动补全不应简单排除——它基于本地数据即可实现 | 本版本暂不做自动补全，但记录理由：先验证核心搜索行为数据再决策。增加成功指标：搜索使用率、搜索转化率、无结果率 |

额外发现：
- 缺少**搜索去重**逻辑（同一关键词保留最近一次）
- 缺少**成功指标**（搜索使用率、转化率、无结果率）
- 缺少场景 S7(结果摘要判断)、S8(输入过程中状态)、S9(搜索历史单条管理)
- 搜索历史5条偏少，建议5条+"查看全部"或8-10条

### 🔧 技术视角（Agent B）
> 评审人: Hermes-Tech | 日期: 2026-05-31

| 维度 | 评价 | 建议 |
|------|------|------|
| 技术可行性 | 整体可行。全文搜索需明确是本地过滤还是远程API——若文章量>几百条，必须后端建全文索引 | 搜索结果由后端API返回（含高亮区间`[{start, end}]`），客户端用AnnotatedString渲染高亮，避免客户端重复做全文匹配 |
| 架构影响 | 与现有MVVM+StateFlow+Hilt一致，无冲突。需新增独立SearchViewModel | UiState用sealed interface建模：`Idle / Loading / Results(items, hasMore) / Empty / Error(message, retry)`；防抖300ms(空关键词零延迟)；历史存储用DataStore |
| 潜在风险 | 按严重度排列：状态管理复杂度(高) > 防抖策略缺失(中) > 历史存储方案未定(中) > 分页方案未定(中) > 高亮实现(低) > 网络重试(低) | P0: 先确认后端API(分页方式/高亮区间返回)；P0: sealed interface设计UiState；P1: 300ms debounce；P1: DataStore存历史；P2: 后端分页则用Paging 3 |

**关键风险详述：**
- **状态管理**：6个场景对应6种状态组合，用data class承载容易产生非法状态（如loading同时有error和items），必须用sealed interface从类型层面杜绝
- **分页**：取决于后端API设计。若cursor/offset分页→Paging 3+RemoteMediator；若全量返回→手动offset/limit+LazyColumn触发
- **高亮**：AnnotatedString+SpanStyle(background=primaryContainer)，匹配用Regex.escape+IGNORE_CASE

### 🎨 UX 视角（Agent C）
> 评审人: Hermes-UX | 日期: 2026-05-31

| 维度 | 评价 | 建议 |
|------|------|------|
| 交互一致性 | 独立搜索页方向与M3 SearchBar模式吻合，但缺动画规范和M3组件选型声明 | 明确使用M3 SearchBar组件；搜索框展开用AnimatedVisibility+fadeIn+expandHorizontally(300ms)；搜索结果页保留可编辑搜索框 |
| 信息架构 | /search与/search?q={keyword}职责分明，但搜索结果页搜索框形态未定义 | 结果页顶部保留可编辑搜索框，用户可原地修改关键词；首页顶部添加SearchBar快捷入口降低搜索发现成本 |
| 视觉与边界 | 覆盖全面但文案规范缺失——空状态/错误/加载均无具体文案 | 关键词高亮用primaryContainer背景+onPrimaryContainer文字色+4dp圆角；空状态主文案"未找到相关结果"+副文案"换个关键词试试"；错误Snackbar含"重试"按钮(Indefinite duration) |

**缺失的UX规格：**
- 搜索历史需支持单条左滑删除(SwipeToDismiss)+全部清空(AlertDialog确认)
- 键盘行为需分场景：点搜索→收起+搜索；点历史→收起+填入+搜索；点空白→仅收起
- 动效：条目入场slideInVertically+fadeIn(stagger 50ms)；搜索结果页支持PullToRefresh
- 分页加载底部用small CircularProgressIndicator+居中+文案"加载更多…"

## 4. 讨论决议

| # | 日期 | 议题 | 结论 | 决策人 |
|---|------|------|------|--------|
| 1 | 2026-05-31 | 搜索结果排序逻辑 | 默认「相关度优先」：标题命中权重 > 正文命中权重。后续可增时间排序选项 | 产品视角提出，三方无异议 |
| 2 | 2026-05-31 | 搜索历史条数 | 保持5条，但增加单条左滑删除 + 「清空全部」（AlertDialog确认）。上线后根据数据调整条数 | 产品建议8-10条，UX强调管理能力 > 条数，调和结论 |
| 3 | 2026-05-31 | 搜索建议/自动补全 | 本版本不做。先验证核心搜索行为数据（使用率、转化率、无结果率），下版本根据数据决策 | 产品建议纳入P1，但实现需要额外开发周期，三方同意延后 |
| 4 | 2026-05-31 | 搜索入口设计 | 首页顶部 SearchBar 快捷入口（点击跳转独立 `/search` 页）。独立搜索页作为主搜索页面 | 产品指出入口缺失，UX建议独立页+快捷入口，三方共识 |
| 5 | 2026-05-31 | 搜索框位置（结果页） | 搜索结果页顶部保留可编辑搜索框，用户可原地修改关键词再次搜索，无需返回 | UX提出，三方共识 |
| 6 | 2026-05-31 | UI 文案规范 | 采用 UX 提供的6状态文案规范（空关键词/无结果/历史空/网络错误/加载中/分页失败） | UX提出，无异议 |
| 7 | 2026-05-31 | 搜索入口动效 | 搜索图标→全宽SearchBar使用AnimatedVisibility(300ms, FastOutSlowInEasing)；条目入场stagger 50ms | UX提出，技术确认可行 |

**分歧记录（已否决的方案）：**
- ❌ 搜索历史10条 → 否决：增加页面复杂度，5条+完善管理能力(单条删除)性价比更高
- ❌ 首版做自动补全 → 否决：先获取用户搜索行为基线数据，避免过早优化
- ❌ 搜索结果页搜索框退化为只读 → 否决：增加二次搜索操作步骤，违背效率目标

## 5. 验收标准

- [ ] AC-1: 在搜索框输入关键词并搜索，返回匹配标题或正文的文章列表，按相关度排序
- [ ] AC-2: 搜索结果中关键词在标题和摘要中高亮显示（primaryContainer 背景色 + 4dp 圆角）
- [ ] AC-3: 搜索无结果时展示空状态（插画 + "未找到相关结果" + "换个关键词试试"）
- [ ] AC-4: 搜索历史保存最近5条（去重），支持左滑单条删除 + AlertDialog 确认清空全部
- [ ] AC-5: 网络错误时展示 Snackbar（含"重试"按钮），保留搜索词供重试
- [ ] AC-6: 搜索结果支持分页加载（滚动到底部自动加载，底部显示加载指示器）
- [ ] AC-7: 搜索结果页顶部搜索框可编辑，用户可原地修改关键词再次搜索
- [ ] AC-8: 搜索框展开/收起使用 300ms 动画（FastOutSlowInEasing），条目入场 stagger 50ms
- [ ] AC-9: 键盘行为分场景正确：点搜索→收起+搜索；点历史→收起+填入+搜索；点空白→仅收起

## 6. 依赖与风险

| 类型 | 描述 | 影响 | 缓解措施 |
|------|------|------|---------|
| 后端依赖 | 搜索接口需要后端提供全文搜索 API（含分页和高亮区间返回） | 高 — 接口未就位则无法联调 | 前端先用 Mock 数据开发，接口就位后再联调；P0 优先确认 API 设计 |
| 性能 | 大量文章时搜索延迟可能影响体验 | 中 | 300ms 防抖、分页加载、搜索请求 cancel 前一个 in-flight 请求 |
| UI 规范 | 搜索页 UI 尚无 Figma 设计稿 | 中 | 先参考 M3 SearchBar 规范实现，后续对齐 Figma |
| 搜索质量 | 后端相关度算法不准导致搜索结果不达预期 | 高 | 内部测试 + 灰度验证；前端兜底：标题匹配优先展示 |
| 关键指标 | 缺少搜索使用率、转化率、无结果率基线 | 中 | 上线前埋点搜索事件，收集 2 周数据后复盘并调整 |
