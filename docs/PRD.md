# 主界面底部版本号显示 — PRD

> **版本:** v1.0-confirmed
> **功能名称:** 主界面底部版本号显示
> **创建日期:** 2026-06-02
> **作者:** Hermes 智能研发工作流

---

## §1 功能概述

在 Android 应用主界面底部固定区域显示当前应用版本号文字 `v1.0.0`，使用户和测试人员能快速识别当前安装的应用版本。

## §2 用户场景

| 场景编号 | 角色       | 场景描述 |
|----------|------------|----------|
| US-01    | 普通用户   | 打开应用主界面，在底部看到版本号 `v1.0.0` |
| US-02    | 测试人员   | 在多个测试版本间切换时，通过底部版本号快速确认当前安装版本 |
| US-03    | 客服/运营  | 引导用户排查问题时，要求用户查看底部版本号以确认版本 |

## §3 范围边界

### 包含
- 在主界面底部固定位置显示版本号文字 `v1.0.0`
- 使用 BuildConfig 动态读取版本号（非硬编码字符串）
- 适配浅色/深色主题

### 不包含
- 点击版本号触发任何交互（如开发者选项）
- 版本更新检测或升级提示
- 多环境版本号差异化（debug/release 暂一致）
- 其他页面显示版本号

## §4 验收标准

| 编号 | 验收项 | 预期结果 |
|------|--------|----------|
| AC-01 | 主界面底部可见版本号 | 打开应用后主界面底部显示 `v1.0.0` 文字 |
| AC-02 | 版本号来源 | 版本号从 BuildConfig.VERSION_NAME 读取，非硬编码 |
| AC-03 | 浅色主题适配 | 浅色主题下版本号文字颜色可辨识（建议灰色 `#9E9E9E` 或次要文本色） |
| AC-04 | 深色主题适配 | 深色主题下版本号文字颜色可辨识（建议浅灰 `#BDBDBD`） |
| AC-05 | 布局无破坏 | 版本号不遮挡主界面其他功能区域，不引起布局异常 |
| AC-06 | 字体大小合理 | 版本号字体较小（建议 12sp），不喧宾夺主 |

## §5 非功能性需求

- **性能:** 版本号显示为静态文本，不增加渲染负担
- **兼容性:** 最低支持 API 24 (Android 7.0)
- **可维护性:** 版本号从 BuildConfig 读取，随构建自动更新，无需手动修改代码

## §6 技术约束

- 项目使用 MVVM + Jetpack Compose 架构（需确认现有主界面是否为 Compose）
- 遵循项目现有主题/颜色 Token 体系
- 若主界面为 XML 布局，使用 TextView + ConstraintLayout 约束到底部

## §7 风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 主界面底部区域已被其他控件占用 | 布局冲突 | 审查现有多语言/多分辨率布局，使用 design-time 预览验证 |
| 深色主题未定义次要文本色 | 深色模式下不可见 | 使用 Material3 `onSurfaceVariant` 或等效 Token |

## §8 术语表

| 术语 | 说明 |
|------|------|
| 主界面 | 应用启动后默认展示的首页 Activity/Fragment/Composable |
| BuildConfig.VERSION_NAME | Android Gradle 构建时自动生成的版本名字段 |

## §9 UI 设计输入

### 页面清单
- **主界面**（已存在，需在底部追加版本号元素）

### 布局规格
| 属性 | 值 |
|------|-----|
| 位置 | 主界面底部，水平居中 |
| 距离底部间距 | 8dp |
| 字体大小 | 12sp |
| 字体颜色（浅色） | `#9E9E9E`（Material Gray 500）或 `onSurfaceVariant` Token |
| 字体颜色（深色） | `#BDBDBD`（Material Gray 400）或 `onSurfaceVariant` Token |
| 不透明度 | 100%（默认） |

### 交互规格
- 无交互，静态展示

### 组件选型
| 组件 | 选型 | 原因 |
|------|------|------|
| 版本号文本 | `Text` (Compose) 或 `TextView` (XML) | 取决于现有主界面技术栈 |
| 主题颜色 | `MaterialTheme.colorScheme.onSurfaceVariant` | 兼容深色/浅色主题 |

### 设计约束
- 版本号元素不可遮挡任何已有功能按钮
- 若底部已有 BottomNavigationBar，版本号需放在其下方（额外 8dp 间距）
- 深色模式下必须在 `@media (prefers-color-scheme: dark)` 或 `darkColorScheme` 中显式设置颜色

### 11.2 产品视角评审

**评分:** 5/10

#### P0 项（必须修正）

| 编号 | 问题 | 说明 |
|------|------|------|
| P0-PM-01 | 优先级未定义，隐含 P0 不合理 | 版本号显示对普通用户价值为零，对测试/客服是低频场景。常驻主界面底部是对 100% 用户屏幕空间的永久占用。建议定为 P2，不应占据独立 Stage |
| P0-PM-02 | 竞品对标缺失，主界面底部版本号违反行业惯例 | 微信/支付宝/抖音/Google 系应用均将版本号放在「设置→关于」深层页面。消费级应用中主界面底部常驻版本号极为罕见，违反 Material3「减少视觉噪音」原则 |

#### P1 项（建议修正）

| 编号 | 问题 | 建议 |
|------|------|------|
| P1-PM-01 | 缺少构建变体信息 | VERSION_NAME 不足以定位问题，建议补充 VERSION_CODE + 构建类型 + Git commit SHA 短码 |
| P1-PM-02 | "不包含多环境差异化"不当 | debug/release 显示相同版本号直接削弱测试场景有效性，建议至少标注构建类型 |
| P1-PM-03 | AC-05 "不引起布局异常"不可量化 | 建议替换为具体场景：5 种屏幕尺寸 / 导航栏+手势模式 / 有/无 BottomBar / 字体缩放 4 档 |
| P1-PM-04 | 缺少无障碍验收标准 | TalkBack 是否播报版本号？视障用户 vs 普通用户需求矛盾，需明确 contentDescription 策略 |
| P1-PM-05 | 缺少 WCAG 对比度数值要求 | AC-03/04 仅说"可辨识"，建议明确对比度 ≥ 3:1（12sp 大文本）或 ≥ 4.5:1（正常文本） |

#### 未覆盖用户场景

| 编号 | 场景 | 影响角色 |
|------|------|----------|
| US-04 | 开发者定位线上问题 | 开发人员 |
| US-05 | 用户反馈问题时截图 | 客服+开发 |
| US-06 | 系统字体缩放（130%/150%） | 所有用户 |
| US-07 | 横屏模式 | 所有用户 |
| US-08 | 首次启动/引导页 | 新用户 |
| US-09 | 深色+省电模式叠加 | 所有用户 |
| US-10 | 分屏/多窗口模式 | 高级用户 |

### 11.3 技术视角评审

**评分:** 6/10
**技术可行性结论:** 可行，但需修正 minSdk 和补齐主题基础设施

#### P0 项（必须修正）

| 编号 | 问题 | 说明 |
|------|------|------|
| P0-TECH-01 | minSdk 声明与实际不符 | PRD §5 声明最低支持 API 24，但项目 build.gradle 实际配置 minSdk=26（Android 8.0）。需统一为 26，PRD 和代码须一致 |
| P0-TECH-02 | 深色主题 darkColorScheme 未配置 | 项目当前仅有 lightColorScheme，未定义 darkColorScheme。AC-04（深色主题适配）当前无法验证，需新建 Theme.kt 补充 darkColorScheme，否则 onSurfaceVariant 在深色模式下会回退到默认值 |

#### P1 项（建议修正）

| 编号 | 问题 | 建议 |
|------|------|------|
| P1-TECH-01 | 布局实现方案待确认 | 主界面若使用 Scaffold + BottomBar，版本号应放在 bottomBar 参数外或使用 Box 叠加。需探索现有 MainActivity 的 Compose 结构后确定方案 |
| P1-TECH-02 | 缺少 WindowInsets 处理 | 全面屏手势导航栏区域需通过 `WindowInsets.navigationBars` 获取安全区，避免版本号被导航栏遮挡 |
| P1-TECH-03 | 缺少测试策略 | 建议至少覆盖：Compose 预览（浅色/深色）、screenshot test（对比度验证）、单元测试（BuildConfig 值读取） |

#### 预估改动文件

| 文件 | 改动内容 |
|------|----------|
| `app/build.gradle.kts` | 确认 VERSION_NAME 配置 |
| `app/src/main/java/.../ui/theme/Theme.kt` | 新建 darkColorScheme |
| `app/src/main/java/.../MainActivity.kt` | 追加版本号 Composable |
| `app/src/main/res/values/strings.xml` | 如需字符串资源 |

### 11.4 UX 视角评审

**评分:** 4/10

#### P0 项（必须修正）

| 编号 | 问题 | 说明 |
|------|------|------|
| P0-UX-01 | 对比度致命缺陷 | PRD 指定的硬编码颜色均不满足 WCAG AA 标准：`#9E9E9E` 在 `#FFFFFF` 背景上对比度仅 2.6:1（需 ≥ 3:1 大文本 / ≥ 4.5:1 正常文本）。应直接使用 `MaterialTheme.colorScheme.onSurfaceVariant` Token，由系统自动处理深浅主题对比度 |
| P0-UX-02 | 信息架构不合理 | 版本号放在主界面底部违反 Android 平台「设置→关于」的通行惯例。PRD 未提供任何决策依据说明为何选择底部而非设置页。需要补充方案对比论证 |
| P0-UX-03 | 布局鲁棒性缺失 | 未考虑：全面屏手势导航栏 WindowInsets（会被遮挡）、系统字体缩放（12sp 放大后可能溢出）、不同 DPI 屏幕占比差异（小屏上 8dp 可能过高） |
| P0-UX-04 | 可访问性全面不达标 | ① TalkBack 焦点策略未定义（是否需要 contentDescription？）② 12sp 在字体放大模式下是否仍可见 ③ 对比度不满足 WCAG 标准 |

#### P1 项（建议修正）

| 编号 | 问题 | 建议 |
|------|------|------|
| P1-UX-01 | "无交互"限制过严 | 建议支持长按复制版本号到剪贴板。用户反馈问题时可直接粘贴版本信息，提升 US-03 场景效率 |
| P1-UX-02 | 纯功能展示缺乏情感设计 | 可考虑半透明背景（如 80% 不透明度）、淡入动画或更优雅的视觉呈现，避免"调试信息"观感 |
| P1-UX-03 | 横屏适配未覆盖 | 横屏时底部区域变窄，版本号可能与内容区重叠，需明确横屏布局策略 |

#### 可访问性评估

| 检查项 | 状态 | 说明 |
|--------|------|------|
| WCAG AA 对比度 (4.5:1) | ❌ 不通过 | `#9E9E9E` 对比度仅 2.6:1 |
| WCAG AA 大文本对比度 (3:1) | ❌ 不通过 | 2.6:1 < 3:1 |
| TalkBack 兼容 | ⚠️ 未定义 | contentDescription 策略待明确 |
| 字体缩放 | ⚠️ 未定义 | 12sp 放大后行为未定义 |
| 触摸目标 | ✅ 通过 | 静态文本，无交互需求 |

#### 平台一致性

| 检查项 | 状态 |
|--------|------|
| Material3 颜色 Token 使用 | ❌ 使用了硬编码颜色而非 onSurfaceVariant |
| Android 版本号展示惯例 | ❌ 底部常驻违背"设置→关于"惯例 |
| 全面屏安全区适配 | ⚠️ 未提及 WindowInsets |
| BottomNavigationBar 共存 | ⚠️ 仅提及 8dp 间距，未明确层级关系 |
